# TinyMed-Net: Lightweight Multi-Class Disease Classification (Diabetes / CKD)

This repository contains the full, real, reproducible pipeline behind the paper
*"TinyML Driven Lightweight Multiclass Disease Classification for Resource
Constrained Healthcare Environments."* Every number in the paper's tables and
figures is generated by the code in this repo, run against the real public
datasets included here (or referenced, for the larger source file).

## What this is (and isn't)

- **Real data, real training, real results.** No fabricated experiments, no
  invented hardware benchmarks.
- **Two conditions only:** Type-2 Diabetes and Chronic Kidney Disease. An
  earlier draft targeted four conditions (also TB and Malaria), but no real,
  accessible public tabular dataset could be found for those two, so they
  were dropped rather than filled in with synthetic data.
- **No physical microcontroller hardware was used.** Model size (Flash/RAM)
  figures are exact, parameter-derived numbers. Latency is a theoretical,
  clearly-labeled compute-bound estimate only. No energy or battery-life
  figures are reported, since these cannot be honestly estimated without
  physical hardware or a validated power model.
- **Not a validated diagnostic tool.** This is a methodological / architecture
  study. It has not undergone prospective clinical validation.

## Headline real results

| Model | Macro-F1 | MCC | AUC-ROC | Size (FP32 / INT8) |
|---|---|---|---|---|
| Logistic Regression | 0.816 | 0.622 | 0.926 | 0.9 KB / — |
| Random Forest | 0.876 | 0.684 | 0.949 | 8.9 MB / — |
| XGBoost | 0.875 | 0.683 | 0.950 | 1.15 MB / — |
| MLP (3-layer) | 0.856 | 0.671 | 0.940 | 172 KB / 42.9 KB |
| **TinyMed-Net (ours)** | 0.856 | 0.642 | 0.939 | **14.8 KB / 3.7 KB** |

TinyMed-Net is competitive with, but not uniformly better than, the tree-based
baselines — the honest story here is an accuracy-per-byte trade-off, not a
clean win on every metric.

**Quantization matters a lot:** naive post-training INT8 quantization
collapses accuracy to near-chance (F1=0.198); quantization-aware training
(QAT) recovers most of it (F1=0.811) at the identical footprint. See
`results/quant_results.json`.

**A real limitation, reported plainly:** training on one population (Kaggle
diabetes cohort) and testing on a demographically distinct one (PIMA, an
all-female 1980s Arizona cohort) causes a severe accuracy collapse
(F1 0.616 → 0.042). See `results/cohort_fairness_results.json`. This model
should not be assumed to generalise across populations.

## Data sources (all genuinely public)

| Source | Condition | N | Citation |
|---|---|---|---|
| PIMA Indians Diabetes | Diabetes | 768 | Smith et al., 1988 (UCI) |
| Diabetes Prediction Dataset | Diabetes | 100,000 (14,500 subsampled here) | Kaggle, iammustafatz |
| Chronic Kidney Disease | CKD | 400 | Rubini, Soundarapandian & Eswaran, 2015 (UCI), DOI: 10.24432/C5G020 |

Raw source files are included in `data/raw/`, except note that
`diabetes_prediction_dataset.csv` is the full 100,000-row Kaggle file
(~3.7 MB) — if you'd rather not host that in your fork, it's fetchable from
Kaggle directly (search "Diabetes Prediction Dataset iammustafatz") and the
pipeline will subsample it identically given the fixed random seed.

## Reproducing the results

```bash
pip install -r requirements.txt

cd src
python build_dataset.py      # -> data/processed/harmonized_raw.csv
python prep_features.py      # -> data/processed/train.csv, test.csv
python train_models.py       # TinyMed-Net + ablations -> results/nn_results.json
python train_baselines.py    # LR / RF / XGBoost -> results/baseline_results.json
python quantize.py           # PTQ vs QAT comparison -> results/quant_results.json
python fairness_cohort.py    # fairness audit + PIMA held-out cohort test
python compute_ece.py        # calibration (ECE) for all models
```

All scripts use `random_state=42` / `torch.manual_seed(42)`, but note that
exact floating-point results can still vary slightly across hardware/library
versions — this is normal and expected, not evidence of irreproducibility.
The paper's headline numbers reflect one specific run; we did not average
over multiple seeds in this revision (see Limitations in the paper).

## Repository structure

```
data/
  raw/                  # original source files, as downloaded
  processed/            # harmonized_raw.csv, train.csv, test.csv
src/
  tinymednet.py         # TinyMed-Net architecture (SE blocks, depthwise-separable convs)
  build_dataset.py      # harmonization of the 3 raw sources
  prep_features.py      # imputation, missingness flags, train/test split
  train_models.py       # TinyMed-Net + architectural ablations (SE/residual/distillation)
  train_baselines.py    # Logistic Regression, Random Forest, XGBoost
  quantize.py           # FP32 vs. naive PTQ vs. genuine QAT comparison
  fairness_cohort.py    # DPD/EOD fairness audit + PIMA held-out cohort generalisation test
  compute_ece.py        # Expected Calibration Error for all models
results/
  *.json                # raw output of each script, as used in the paper's tables
```
